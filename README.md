# 增量目录扫描（从 0 实现）

起始环境只有这份说明、`samples/**` 和 `.gitignore`，没有实现代码：增量扫描的库、命令行入口和一页原生 HTML/内联 SVG 的变更树页面都从零写，用 Python 3.13 标准库，不引第三方、不加构建。扫描把上次的快照与现在的目录比出新增、修改、删除、未变四类：全量重扫不再走，漏检也不能再有。

## 一、范围

做：遍历目录树；快照落盘、可重载；按分级链产出四类变更集合；页面数据；命令行入口；页面渲染。

不做：不识别重命名与移动（改名、搬家一律记「删旧 + 增新」）；不做同步与回滚（只报告，不改被扫目录）；不监听文件事件；不跟踪目录（空目录不产生记录，目录 mtime 不参与判定）；不跟随符号链接（非普通文件不入快照也不进结果）；不比权限与扩展属性；不引第三方依赖、不加构建步骤。

## 二、口径与公式

- 路径相对扫描根、`/` 分隔、UTF-8；`size` 为字节数；`mtime` 用 `st_mtime_ns` 纳秒整数，严格相等才算没变（差 1 纳秒也算变）；摘要是对原始字节算的 SHA-256 小写十六进制。
- 分级判断链（逐路径按序走；**零漏检**指大小或时间戳有差异的改动一条不漏，只改时间戳的伪变更必须记 `=`）：
  1. 快照有、磁盘没有 → `-`；磁盘有、快照没有 → `+`；
  2. `size` 不同 → `~`（已证明内容不同，不读内容）；
  3. `size` 相同、`mtime_ns` 相同 → `=`（唯一允许跳过内容比对的出口）；
  4. `size` 相同、`mtime_ns` 不同 → 必须读内容算 sha256 再裁：同快照摘要记 `=`，不同记 `~`。
- 哈希次数口径：一次 `scan` 里「读过内容的文件个数」，同一文件只计 1 次（判定读与写新快照读算同一次）。
- 确定性：不读时钟、不用随机数、不依赖遍历顺序；输出按路径码点升序，同一输入两遍逐字节相同。

## 三、状态机与数据结构

- `Snapshot`：`version` 加 `entries`（路径 → `(size, mtime_ns, sha256)`），只装普通文件。
- `ScanResult`：`added`/`modified`/`removed`/`unchanged` 四条有序路径表、`hashes` 计数、`nodes`。
- 一次 `scan`：重载并校验快照 → `scandir` 递归取 `(size, mtime_ns)` → 逐路径定论（疑似区读一次内容，摘要留用）→ 写变更集合、页面数据、可选新快照 → 打 `STAT`。
- 新快照的条目等于本轮真实存在的文件，`~` 用本轮摘要、`=` 沿用快照摘要；输出先写临时文件再原子替换，失败不留半成品。

## 四、输入输出与文件格式

本节文本文件一律 UTF-8 无 BOM、LF、末行有换行；数字十进制。

### 4.1 样例树 `samples/trees/<案例>/`

- `live/`：本轮目录树（真实文件，按字节处理；混有 LF 与 CRLF，也有不带末尾换行的）。
- `live.times.tsv`：每行 `<路径>\t<mtime_ns>`，按路径升序覆盖 `live/` 下每个文件；git 不保存修改时间，**跑扫描前必须按它复原各文件 mtime**（`os.utime(name, ns=(mtime_ns, mtime_ns))`）。
- `snapshot.tsv`：上一轮快照，本次比对基线。

### 4.2 快照文件

第 1 行 `#rescan-snapshot v1`，第 2 行条目数 `n`，接着 `n` 行 `<路径>\t<size>\t<mtime_ns>\t<sha256>`（路径升序且唯一），末行是**正文摘要**：第 3 行到第 `n+2` 行的原始字节（含行尾 `\n`）拼接后取 SHA-256。

重载要校验版本行、条目数与行数、`size` 与 `mtime_ns` 的十进制写法、64 位小写十六进制摘要、路径不以 `/` 开头且不含 `\` 且不重复；任一条不满足（含读不到、摘要对不上、被截断、版本号被改）都报错退出，不得当成有效基线。

### 4.3 变更集合

每行 `<标记> <路径>`：`+` 新增、`~` 修改、`-` 删除、`=` 未变；只列普通文件；按路径升序；无表头与空行。

### 4.4 页面数据 `data.json`

字段：`tree`（扫描根目录名）、`budget`（预算，没给为 `null`）、`hashes`（本次读内容的文件数）、`counts`（四类计数）、`colors`（四类颜色，页面只能用这组）、`nodes`（数组）。

`nodes` 每项形如 `{"path":"docs/a.txt","kind":"file","depth":1,"status":"modified"}`：`kind` 为 `dir` 或 `file`，`depth` 是相对根的层级（根的直接子项为 0），目录 `status` 为 `null`、文件取四类之一；`path` 相对扫描根、按路径升序；已删除的文件及其父目录也要出现。

### 4.5 命令行与页面

```
python -m rescan snapshot --tree <目录> --out <快照文件>
python -m rescan scan --tree <目录> --snapshot <快照文件> --changes <变更集合文件> --data <data.json> [--budget <整数>] [--write-snapshot <新快照文件>]
```

`scan` 往 stdout 打一行 `STAT|hashes=…|budget=…|added=…|modified=…|removed=…|unchanged=…`（预算没给时写 `-`）；失败（快照不可用、目录读不了等）退出码非 0 且不写输出。输出文件不得写进被扫目录。

页面放 `web/index.html`（原生 HTML + 内联 SVG）：仓库根执行 `python -m http.server 8000 --directory web`，打开 `http://localhost:8000/`；页面 `fetch` 同目录 `data.json`（`file://` 下会被拦）。只渲染不重算：树按 `depth` 缩进，文件节点用 `colors` 着色标类别、删除的节点也画，页头给出 `hashes / budget`（没给预算就写明）、四类计数与图例；数字全取自 `data.json`。

## 五、性能与验收口径

Windows + Python 3.13、单进程单线程；合成大树（50 万文件、约 400 MiB、约 5% 改动）单次 `scan`（含写新快照）≤ 120 秒、峰值内存 ≤ 512 MiB；按块读取，未变文件 0 次内容读取。

1. 每组样例先复原 mtime，各跑一次 `scan`，输出与 `samples/expected/<案例>.txt` 逐字节相同；哈希次数不超过 `expected-budget.txt` 的上界（`<案例>\t<上界>`，末行 `total` 为合计），上界只比必要次数多留一次余量，全量哈希必然超。
2. 幂等：加 `--write-snapshot` 跑一遍，再用新快照跑同一目录，第二轮必须全 `=`、哈希 0 次，两轮快照逐字节相同。
3. 确定性：同一输入连跑两遍（含换 `PYTHONHASHSEED`），变更集合、`data.json`、新快照与 `STAT` 行逐字节相同，计数与变更集合行数一致。
4. 坏快照：正文摘要改一个字符、条目数改小、删掉中间一行、改掉版本号，四种都必须非零退出且不留输出。
5. 页面与测试：用 `06-add-remove` 出一份 `data.json` 并核对页面；测试写在 `unittest` 里，跑 `python -m unittest`，只读 `samples/**`，写就写 `var/`。

## 六、样例说明

`samples/trees/<案例>/` 与 `samples/expected/<案例>.txt` 一一对应，连 `=` 的未变行也逐条列出；覆盖仅改内容、仅改时间戳、重命名、整目录移动、批量恢复时间戳、新增与删除。

- `01-content-only`（10 个文件，上界 3）：仅改内容，同字节长度改写两条 `~`、其余 8 条 `=`。
- `02-mtime-only`（12 个文件，上界 4）：仅改时间戳，`mtime` 被批量改写（含只差 1 纳秒的一条），必须记 `=`。
- `03-rename`（9 个文件，上界 2）：重命名 `docs/draft.txt` → `docs/final.txt`，记 `-`、`+` 两条。
- `04-dir-move`（9 个文件，上界 4）：`old/util/` 三个文件整体挪到 `lib/util/`，记 3 条 `-` 与 3 条 `+`。
- `05-restore-mtime`（11 个文件，上界 5）：4 个文件 `mtime` 被恢复工具改写，3 个没变、1 个真改过而 `mtime` 被写回旧值（靠 `size` 判 `~`）。
- `06-add-remove`（8 个文件，上界 4）：新增 3 个（含中文加空格文件名）、删除 2 个、其余 5 条 `=`。

`samples/notes.md` 是现场记录，只作背景，不作为口径。
